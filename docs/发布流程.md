# 打包与发布流程

**tc1911 个人 pacman 源**的运行手册：从「有个新东西要发」到「客户端能装上」。

---

## 一、仓库定位与产物去向

本仓库是**独立于任何项目的个人软件源**：只存配方（PKGBUILD / 构建脚本 / 补丁），不存二进制。

| | 位置 | 说明 |
|---|---|---|
| 本地 | `~/项目/tc191-pkgs` | |
| 远程 | `git@github.com:tc1911/tc191-pkgs.git` | |
| 分支 `main` | 配方 | 跟随代码演进 |
| 分支 `gh-pages` | 打包好的二进制 | **滚动覆盖**（`--force`），体积恒定 |

**pacman 源地址**：`https://tc1911.github.io/tc191-pkgs/`

> **为什么不用 GitHub Release 当源**：Release 的附件区是用来放「版本说明 + 附件」的，当软件源用会堆一屏二进制，而且每次发版都在 git 历史里多囤一份。`gh-pages` 是滚动覆盖的，仓库体积不随发版增长。

**可选第二条通道**：通用 `.tar.gz`（给非 Arch 用户），发布到归档仓库 `tc1911/vtb-bin` 的 Release 附件。GitHub slug 由 `release_binaries.sh` 的 `REPO` 覆盖：

```bash
REPO=tc1911/别的仓库 bash scripts/release_binaries.sh
```

### 脚本不再写死仓库路径

四个脚本里的仓库根目录都**从脚本自身位置推导**（脚本都在 `<root>/scripts/` 下）：

```bash
REPO="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"
```

`release_binaries.sh` 里这个变量叫 `REPO_DIR`。所以**搬目录、改目录名都不用改脚本**。注意 `release_binaries.sh` 另有一个 `REPO`，那个是**归档仓库的 GitHub slug**，不是本地路径，两个别混。

## 二、客户端接入

`/etc/pacman.conf` 末尾：

```ini
[tc191]
SigLevel = Optional TrustAll
Server = https://tc1911.github.io/tc191-pkgs/
```

```bash
sudo pacman -Syu
sudo pacman -S open-vt-bin        # 例如
```

非 Arch：

```bash
sudo tar xzf open-vt-bin-*.tar.gz -C /     # 装法，不进 pacman 数据库
```

> 用 `-C /` 解包意味着以后升级/卸载要手动处理，pacman 数据库里没有记录。

## 五、发布全流程

### 第 1 步：构建各包的 `.pkg.tar.zst`

```bash
cd ~/项目/tc191-pkgs

bash open-vt-bin/make_openvt_pkg.sh        # → ~/vtb/归档/open-vt-bin/
bash psd2live-bin/make_psd2live_pkg.sh     # → ~/vtb/归档/psd2live-bin/
bash auto-vtb-bin/make_auto_vtb_pkg.sh     # → ~/vtb/归档/auto-vtb-bin/（先构建 app image，慢）
cd openseeface && makepkg -f               # → ~/opt/openvt-pkg/openseeface/
```

`openseeface` 是唯一走标准 `makepkg` 的，产物目录也和其他三个不一样——**改路径时要同步 `release_github.sh` 里的 `OPENSEEFACE_DIR`**。

### 第 2 步：发布到 pacman 源（一步到位）

```bash
bash scripts/publish_pages.sh              # 先跑 release_github.sh，再推 gh-pages
bash scripts/publish_pages.sh --no-build   # 直接用现有 dist/
```

`publish_pages.sh` 干的事：

1. 调 `release_github.sh` 生成 `dist/`（除非 `--no-build`）
2. 在 `/tmp` 建独立工作区，`cp -p dist/*` 过去（**完全不碰 main 的工作区**）
3. 写 `index.html`（接入说明 + 文件清单 + 大小）
4. `touch .nojekyll`（不加这个，Pages 会拿 Jekyll 处理这个纯二进制镜像站）
5. `git init -b gh-pages` → 提交 → `push --force` 到远程
6. 对 `<db>.db` / `<db>.files` / `SHA256SUMS` 各发一次请求，**打印 HTTP 状态码自验**

首次发布后要去 GitHub 仓库 Settings → Pages 确认源是 `gh-pages` 分支根目录。

### 第 3 步：发布通用 tar.gz（可选）

```bash
bash scripts/release_binaries.sh                    # 默认 TAG=v0.2.0
TAG=v0.3.0 bash scripts/release_binaries.sh
COMPRESSOR=pigz bash scripts/release_binaries.sh    # 快很多，需装 pigz
FORCE_REBUILD=1 bash scripts/release_binaries.sh    # 强制重打
SKIP_UPLOAD=1 bash scripts/release_binaries.sh      # 只打包不上传
```

**不重新编译**：把 `dist/` 里每个 `.pkg.tar.zst` 解开 → 丢掉 pacman 自己的元数据（`.PKGINFO` / `.BUILDINFO` / `.MTREE` / `.INSTALL`）→ 剩下的 `usr/` 树重新压成 `.tar.gz` → `gh release create/edit` + `gh release upload --clobber` → 最后逐个验证下载地址返回 200。

## 六、`release_github.sh` 细节（核心脚本）

五个阶段，**任一步失败整个流程就退出**：

| 阶段 | 动作 | 关键点 |
|---|---|---|
| 1/5 | `rm -rf dist/` 重建 | dist 每次全清，保证内容就是本批 |
| 2/5 | 从 `PKGDIRS` 收集包 | **数量对不上就退出**（防静默漏包）|
| 3/5 | `repo-add ${DBNAME}.db.tar.gz ./*.pkg.tar.zst` | 见下方「符号链接坑」 |
| 4/5 | 逐个包比对索引里的 SHA256SUM/CSIZE 与文件实际值 | 不符 → 退出 |
| 4.5/5 | 生成对应源码（GPL-3 义务）| 见第七节 |
| 5/5 | `sha256sum` 写 `SHA256SUMS` | 覆盖包和对应源码 |

校验用 `bsdtar -xOf <db>.tar.gz <key>/desc` 读索引字段。注意**索引里的目录名是 `<name>-<ver>-<rel>`，不带架构**，而文件名带 `-x86_64`，所以要先 `key=${key%-x86_64}` 剥掉。

### 数据库名

由 `DBNAME` 控制，默认 `tc191`：

```bash
DBNAME=vtb bash scripts/release_github.sh
```

切名字时，**客户端 `pacman.conf` 的 `[节名]` 和 `Server` 路径都要同步改**，`gh-pages` 上的文件名也跟着变。

## 七、对应源码（GPL-3 第 6 条，不是可选项）

`psd2live-bin` 不是上游原样二进制——构建它的工作树相对上游提交 `c8ad876` 有改动（`RigBuilder.kt` / `Moc3RenderOrderLowering.kt` / `gradle-wrapper.properties` 各一行，外加 `gradlew` 权限位）。GPL-3 要求分发目标代码时提供**实际用于构建的那份源码**，只给上游链接不满足义务。

```bash
bash scripts/make_corresponding_source.sh
```

产出 `dist/psd2live-<ver>.r1.<commit>-corresponding-source.tar.zst`，内含：

- `git archive HEAD` 的完整树
- 覆盖上工作树的改动（按 `git diff --name-only` 逐个 `install` 进去）
- 补丁副本 `psd2live-groupindex-fix.patch`
- `README-corresponding-source.txt`（写明上游、基准提交、改动 diffstat、重建命令）

**源码树不在时会自动复用归档**（`$ARCHIVE_DIR`）。理由：对应源码是**按包版本固定**的——同一个 `psd2live-bin 0.7.1.r1.c8ad876` 永远对应同一份源码，为了往新仓库重发而重新生成一遍没有意义，重建还可能引入差异。

## 八、新增一个包要动哪些地方

| # | 动作 | 位置 |
|---|---|---|
| 1 | 建 `<包名>/` 目录，放 `PKGBUILD` + 构建脚本 | `<仓库>/<包名>/` |
| 2 | 构建脚本把 `.pkg.tar.zst` 产出到 `OUT` | 脚本内部 |
| 3 | **在 `PKGDIRS` 数组里加一行** | `scripts/release_github.sh` |
| 4 | 包里若有 GPL 组件且构建时改过源码 → 加对应源码生成 | `scripts/make_corresponding_source.sh` |
| 5 | README 的包列表加一行 | `README.md` |
| 6 | 跑 `bash scripts/publish_pages.sh` | — |
| 7 | 走 tar.gz 通道（可选）| `release_binaries.sh` 自动收录 `dist/` 下所有包，无需登记 |

**第 3 步最容易忘**。`release_github.sh` 有数量断言 `[ ${#PKGS[@]} -eq ${#PKGDIRS[@]} ]`，忘了加会报「只找到 N 个包」而不是静默漏包（故意的）。

`release_binaries.sh` 反过来：它遍历 `dist/*.pkg.tar.zst`，不用登记，但**dist 里有什么就发什么**。

## 九、踩过的坑

### 1. GitHub Release 存不了符号链接

`repo-add` 产出的 `<db>.db` / `<db>.files` 是指向 `.tar.gz` 的**软链**。Release 不接受符号链接，所以脚本额外做一份实体副本：

```bash
rm -f "${DBNAME}.$x"                          # 不先删，cp 会报「同一文件」
cp -f "${DBNAME}.$x.tar.gz" "${DBNAME}.$x"
```

**两个都要上传。** pacman 先找 `<db>.db`，找不到才回落 `<db>.db.tar.gz`。

### 2. `tar -tzf | grep -q` 在 `pipefail` 下误报失败

`grep -q` 找到即退，`tar` 接着写就被 SIGPIPE 干掉，`set -o pipefail` 判定整条管道失败 → 明明打好的 tar.gz 被拦下不上传。

正确写法：**先把列表读进变量再判断**

```bash
listing=$(tar -tzf "$f") || { echo "解不开"; exit 1; }
case "$listing" in *"./usr/"*) ;; *) echo "没 usr/"; exit 1 ;; esac
```

### 3. 别用 mtime 判断「已经打过」

`install -m644` 会把包的 mtime 刷成当前时间，导致每次发布都重压 6 分钟。改用**存在 + `tar -tzf` 能完整列出**当判据。

### 4. `gh-pages` 必须加 `.nojekyll`

否则 Pages 走 Jekyll 处理，纯二进制镜像站会被搞坏。

### 5. `github.com` 直连不通

`release_binaries.sh` 开头就导出代理，`gh` 和 `curl` 都靠它：

```bash
export HTTPS_PROXY=http://127.0.0.1:7890
export HTTP_PROXY=http://127.0.0.1:7890
export NO_PROXY=127.0.0.1,localhost
```

代理会抖，所以 `gh auth status` 探测三次再放弃。

### 6. 幂等性

重跑不能炸：

- `gh release view` 存在就复用，否则 `create`
- `gh release edit` 刷新说明（否则新加的包不出现在描述里）
- 上传前对比 assets 的名字 + 大小，**只传缺的或大小对不上的**（避免重传几百 MB）

### 7. 多行 Release 说明别用 `$(cat ...)`

`gh release` 会吃掉行首字符。用 `sed 's/^/| /'` 给每行加前缀，或在变量里显式保留换行。

## 十、环境依赖

| 命令 | 用途 | 包 |
|---|---|---|
| `repo-add` | 生成仓库索引 | `pacman`（自带）|

## 十一、验证清单

```bash
# 1. 源上三个文件都应是 200（publish_pages.sh 会自动打印）
for f in tc191.db tc191.files SHA256SUMS; do
  curl -s -o /dev/null -w "%{http_code}  $f\n" "https://tc1911.github.io/tc191-pkgs/$f"
done

# 2. 源上的校验和
curl -s https://tc1911.github.io/tc191-pkgs/SHA256SUMS

# 3. 真的能装（换台干净机器 / 容器最保险）
sudo pacman -Syu && sudo pacman -S <包名>

# 4. tar.gz 通道：Release 每个附件地址返回 200（release_binaries.sh 自动打印）
```

`publish_pages.sh` 的 `git push --force` 是滚动覆盖，所以**旧版本从源上消失**——客户端 `pacman -Syu` 只会拿到当前这一批。要留旧版本就靠 tar.gz 通道（那是按 TAG 归档的）。
